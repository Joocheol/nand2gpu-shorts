# 표준 제작 작업 흐름

이 문서는 `docs/project-brief.md`의 기획 원칙을 실제 에피소드 제작에 적용하기 위한 표준 절차다. 모든 단계는 **기획 → 명세 → 음성 → 애니메이션 → 미리보기 → 음량·결합 → 최종 검증** 순서로 진행하며, 각 승인 관문을 통과하기 전에는 다음 단계로 넘어가지 않는다.

## 1. 역할 분담

### ChatGPT Work

- 에피소드 주제, 핵심 질문, 결론과 설명 순서를 기획한다.
- 내레이션 대본과 화면 설명을 작성한다.
- 기술 내용의 정확성, 일반 대중의 이해 가능성, 교육적 흐름을 검토한다.

### Codex

- 승인된 기획과 대본을 프로젝트 파일로 구현한다.
- TTS(Text-to-Speech, 음성 합성) 생성, Manim 장면 구현, 렌더링과 테스트를 담당한다.
- FFmpeg 후처리와 결합, ffprobe 기반 기술 검증 결과를 보고한다.
- 승인되지 않은 콘텐츠 결정이나 다음 장면 구현을 임의로 진행하지 않는다.

### 사용자

- 핵심 질문, 결론, 대본, 음성 시안과 미리보기를 승인한다.
- 에피소드별 장면 수, 길이, 음성 및 공개 버전을 최종 결정한다.
- 각 승인 관문에서 수정 또는 다음 단계 진행 여부를 결정한다.

## 2. 기획: 핵심 질문과 결론

구체적인 대본이나 애니메이션을 만들기 전에 다음 두 문장을 먼저 확정한다.

1. 시청자가 영상에서 답을 얻어야 하는 **핵심 질문**
2. 영상을 본 뒤 시청자가 스스로 설명할 수 있어야 하는 **하나의 결론**

설명은 사용법보다 왜 그런 구조가 필요하고 왜 그렇게 설계되었는지를 먼저 다룬다. 한 영상에는 질문 하나, 핵심 시각적 변화 하나, 결론 하나만 둔다.

> **승인 관문 1:** 사용자에게 핵심 질문, 결론과 설명 범위를 승인받기 전에는 에피소드 명세를 확정하지 않는다.

## 3. 에피소드 명세 작성

에피소드 명세는 `episodes/NNN-slug/spec.md` 경로에 작성한다. `NNN`은 3자리 에피소드 번호이고 `slug`는 짧은 영문 식별자다.

명세에는 다음 내용을 포함한다.

- 제목, 핵심 질문, 결론과 설명 범위
- 에피소드 전체 길이와 장면 수
- 장면별 시간 구간
- 확정 내레이션 문구
- 장면별 핵심 시각적 변화와 그 장면이 필요한 이유
- 읽기와 화면 이해를 위한 무음 구간
- 화면에 처음 등장하는 약어·전문용어의 원래 이름
- 색상 외에 모양, 선, 기호와 위치를 사용하는 접근성 규칙
- 다음 에피소드에서 다룰 내용과 이번 에피소드에서 다루지 않을 범위

> **승인 관문 2:** 전체 명세와 내레이션 문구를 승인받기 전에는 음성을 생성하지 않는다.

## 4. 영상 길이와 플랫폼 기준

- 기본 목표 길이는 `40~60초`로 한다.
- 설명에 필요한 경우 최대 `3분`까지 확장할 수 있다.
- 각 영상의 실제 길이와 장면 수는 해당 `episodes/NNN-slug/spec.md`에서 결정하며, 모든 에피소드에 동일한 값을 고정하지 않는다.
- YouTube Shorts에 동시 게시할 수 있는 상한인 `3분`을 이 프로젝트의 기술적 상한으로 사용한다.
- 화면은 기본적으로 `9:16` 세로형으로 제작한다.
- 1분을 초과하는 YouTube Short에 활성 저작권 주장이 있는 음악이나 콘텐츠가 포함되면 차단될 수 있으므로 게시 전에 권리 상태를 확인한다.
- TikTok은 업로드 영상이 최대 `60분`, 앱에서 직접 촬영한 영상이 최대 `10분`이지만, 이 한도를 프로젝트의 목표 길이로 사용하지 않는다.
- 기준 확인일: `2026-08-30`

출처:

- [YouTube 도움말 — 3분 YouTube Shorts 이해하기](https://support.google.com/youtube/answer/15424877)
- [TikTok 도움말 — Camera tools](https://support.tiktok.com/en/using-tiktok/creating-videos/camera-tools)

## 5. 내레이션 우선 원칙

애니메이션의 실제 타이밍은 승인된 음성을 기준으로 설계한다. 따라서 내레이션 음성을 먼저 확정한 뒤 Manim 장면을 구현한다.

- 발화문은 화면용 숫자와 실제 발음용 표현을 구분해 작성할 수 있다.
- 숫자, 약어, 자릿값과 전문용어의 발음을 명확히 지정한다.
- 장면 끝에는 화면을 읽을 수 있는 짧은 무음 구간을 확보한다.
- 승인된 원본 음성 파일은 덮어쓰거나 직접 후처리하지 않는다. 새 시안이나 결합본은 별도 파일로 만든다.

## 6. TTS 생성과 검토

1. 확정 발화문, 모델, 음성, 속도, 말투 지시와 출력 형식을 기록한다.
2. 차분하고 명료한 교육 영상 말투를 기본으로 하며 과장된 감정, 음악과 효과음은 넣지 않는다.
3. 숫자와 자릿값이 또렷이 구분되는지 직접 재생해 확인한다.
4. `ffprobe`로 코덱, 샘플레이트, 채널 수와 전체 길이를 확인한다.
5. `silencedetect`로 마지막 실제 발화 종료 시점과 뒤쪽 무음 길이를 확인한다.
6. 목표 시간을 넘겨도 별도 승인 없이 자르기, 시간 압축 또는 재생성을 하지 않는다.
7. 여러 시안이 있으면 원본을 보존한 채 새 파일명으로 생성하고 사용자가 하나를 채택한다.

> **승인 관문 3:** 발음, 말투, 속도와 실제 발화 길이를 사용자가 승인하고 음성 파일을 채택하기 전에는 Manim 타이밍을 확정하지 않는다.

## 7. 승인 음성 기준의 Manim 구현

- 채택된 음성의 발화 시작, 문장 전환과 종료 시점을 기준으로 장면의 애니메이션 구간을 나눈다.
- 한 장면에는 명세에 기록된 하나의 핵심 시각적 변화만 구현한다.
- 9:16 화면에서 큰 글자와 충분한 안전 여백을 사용한다.
- 색만으로 상태를 구분하지 않고 숫자, 위치, 테두리 모양, 선과 기호를 함께 사용한다.
- 한글 글꼴은 Manim/Pango에서 실제 사용 가능 여부를 먼저 확인하고 승인된 우선순위에 따라 선택한다.
- 최종 해상도와 프레임률은 에피소드별 승인 전까지 전역 설정 파일에 고정하지 않는다.
- 승인 범위 밖의 장면이나 다음 에피소드를 미리 구현하지 않는다.

## 8. 장면별 저해상도 미리보기

장면을 구현할 때마다 전체 영상보다 먼저 저해상도 미리보기를 렌더링한다. 미리보기에서는 다음을 확인한다.

- 휴대전화 화면에서 제목, 숫자와 보조 문구를 읽을 수 있는가
- 화면 가장자리와 플랫폼 UI를 고려한 안전 여백이 충분한가
- 핵심 변화가 한눈에 보이고 불필요한 요소가 경쟁하지 않는가
- 색을 보지 않아도 모양, 위치, 선과 기호로 상태를 구분할 수 있는가
- 발화가 끝난 뒤 화면을 이해할 무음·고정 구간이 있는가
- 해상도, 프레임률과 장면 길이가 명세와 일치하는가

> **승인 관문 4:** 장면별 저해상도 미리보기의 내용, 타이밍과 휴대전화 가독성을 승인받기 전에는 최종 결합 또는 다음 장면 구현으로 넘어가지 않는다.

## 9. 음량 정규화와 FFmpeg 결합

승인된 원본 음성은 보존하고 결합 과정에서만 후처리한다.

1. FFmpeg `loudnorm` 1차 패스로 원본의 통합 음량, 최고 음량, LRA와 임계값을 측정한다.
2. 측정값을 입력한 2차 패스로 통합 음량 `−16 LUFS`, 최고 `−1.5 dBTP`를 목표로 정규화한다.
3. 오디오는 AAC, 모노, 48kHz로 출력한다.
4. 음성이 장면보다 짧으면 뒤에 무음을 채우고 장면의 승인된 전체 길이에 맞춘다.
5. 화면을 바꾸지 않을 때는 영상 스트림을 재인코딩하지 않고 복사한다.
6. 정규화·결합 결과는 `previews/` 아래의 새 파일로 저장한다.

음량 정규화, 무음 추가와 결합은 원본 WAV나 기존 무음 영상을 수정하지 않는 방식으로 수행한다.

## 10. 기술 검증

결합 후 `ffprobe`로 다음 항목을 확인한다.

- 컨테이너와 영상·오디오 코덱
- 9:16 해상도와 승인된 픽셀 크기
- 프레임률과 총 영상 프레임 수
- 영상, 오디오와 컨테이너의 정확한 길이
- 오디오 샘플레이트와 채널 수

추가로 최종 오디오의 LUFS와 dBTP를 다시 측정한다. 영상 스트림을 복사한 경우 원본과 출력의 영상 스트림 해시를 비교해 화면과 애니메이션이 변경되지 않았는지 검증한다.

> **승인 관문 5:** 콘텐츠 검토와 기술 검증을 모두 통과하기 전에는 공개·배포용 최종 렌더링이나 다음 제작 단계로 넘어가지 않는다.

## 11. AI 생성 음성 공개

AI로 생성한 음성을 사용하는 공개 영상에는 AI 생성 음성임을 명확히 밝힌다. 플랫폼 설명란, 영상 내 고지 또는 게시 설정 등 실제 시청자가 확인할 수 있는 위치에 표시하며, 고지 없이 공개하지 않는다.

## 12. API 키 보안

- OpenAI API 키는 macOS 키체인의 서비스 `openai-api-key`, 현재 macOS 사용자 계정에서만 읽는다.
- `security find-generic-password`로 읽은 키는 요청을 실행하는 셸 프로세스의 임시 변수로만 사용한다.
- 키의 전체 또는 일부를 화면, 명령 로그, 오류 로그에 출력하지 않는다.
- 키를 프로젝트 파일, `.env`, 셸 설정 파일, 임시 요청 파일이나 생성물에 저장하지 않는다.
- `set -x`를 사용하지 않는다.
- API 오류 응답은 최종 미디어 파일로 남기지 않고 안전하게 제거한다.

## 13. 승인 관문 요약

1. 핵심 질문·결론·범위 승인
2. 에피소드 명세·내레이션 문구 승인
3. TTS 발음·속도·길이 및 사용할 음성 승인
4. 장면별 저해상도 미리보기·휴대전화 가독성 승인
5. 음량 결합본·기술 검증·공개 고지 승인

어느 단계에서도 현재 관문이 승인되지 않은 상태로 다음 단계의 파일이나 미디어를 임의 생성하지 않는다.
