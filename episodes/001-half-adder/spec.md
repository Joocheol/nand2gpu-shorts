# 001. 9 다음에는 왜 두 자리가 될까?—기호가 끝나면 올림이 생긴다

## 기본 구성

- 대상: 2진수를 모르는 일반 대중
- 목표 길이: 미확정 — 새 TTS의 실제 발화 시간을 사용자가 승인한 뒤 확정한다.
- 장면 수: 4
- 기본 화면 형식: 9:16 세로형
- 핵심 질문: 한 자리에서 쓸 수 있는 기호가 끝나면, 다음 수는 어떻게 적을까?
- 결론: 이진수에서는 한 자리에서 사용할 수 있는 기호가 0과 1 두 개뿐이므로, 1 다음에 바로 올림이 일어난다.
- 핵심 시각적 변화: 한 자리 숫자 칸이 두 자리로 늘어난다.
- 설명 순서: 9 다음에 두 자리가 생기는 익숙한 현상 → 자리 올림의 이유 → 한 자리에서 사용할 기호를 0과 1로 축소 → 같은 올림이 1 다음에 발생 → 이진수 1 더하기 1의 결과 → 다음 에피소드 질문
- 범위: 자리 올림의 직관과 이진수 `1 + 1 = 10₂`의 결과까지만 설명하고 회로 구현은 다루지 않는다.

## 설명 원칙

- 익숙한 십진수의 `9 + 1 = 10`에서 출발해, 한 자리에서 사용할 기호가 끝나면 새 자리를 만든다는 이유를 먼저 보여 준다.
- 한 자리에서 사용할 수 있는 기호 목록이 `0~9`에서 `0, 1`로 줄어드는 시각적 변화를 통해 이진수의 더 이른 올림을 설명한다.
- `진법(base)`과 `자리값(positional notation)`의 정의는 설명하지 않고 자리 칸의 변화로 이해시킨다.
- 십진수의 `10`은 음성에서 “십”, 이진수 화면의 `10₂`는 음성에서 “일 영”으로 구분한다.
- 반가산기(Half Adder), XOR(Exclusive OR), AND, NAND는 이번 에피소드에서 언급하거나 설명하지 않는다.
- 다음 편 예고는 마지막 한 문장으로만 제시한다.

## 확정 내레이션

“숫자 9에 1을 더하면, 왜 자리가 하나 늘어날까요?

한 자리에서 쓸 수 있는 기호가 0부터 9까지뿐이기 때문입니다. 9까지 다 쓰면 그 자리는 0으로 돌아가고, 왼쪽에 새 자리를 만들어 1을 올립니다. 그래서 왼쪽에는 1, 오른쪽에는 0이 놓입니다. 이렇게 만든 수를 우리는 ‘십’이라고 읽습니다.

그런데 한 자리에서 0과 1만 쓸 수 있다면 어떨까요? 1까지 쓰는 순간 벌써 기호가 끝납니다. 같은 규칙으로 오른쪽은 0으로 돌아가고, 왼쪽에는 1을 올립니다.

화면에는 똑같이 1과 0이 남지만, 여기서는 ‘십’이 아니라 ‘일 영’이라고 읽겠습니다. 이진수의 ‘일 영’은 우리가 평소 세는 2입니다.

그래서 이진수에서 1 더하기 1은 ‘일 영’입니다. 계산이 이상한 게 아니라, 한 자리에서 쓸 수 있는 기호가 두 개뿐이라 올림이 더 일찍 일어난 겁니다.

그렇다면 컴퓨터는 이 올림을 어떻게 만드는 걸까요?”

## 장면 구성 개요

새 TTS가 승인되기 전까지 모든 초 단위 타이밍은 미확정이다. 장면의 시작, 전환과 종료 시점은 승인된 WAV의 실제 발화 시간을 기준으로 정한다.

### 장면 1 — `9 + 1`에서 두 자리 `10`으로

- **시간:** 미확정 — 새 TTS 승인 후 결정
- **핵심 시각적 변화:** 한 자리 칸의 `9`에 `1`을 더하면 기존 칸이 `0`으로 돌아가고, 왼쪽에 `1`이 들어갈 새 칸이 열리며 `10`이 된다.
- **필요한 이유:** 이미 익숙한 현상에서 “한 자리의 기호가 끝나면 왼쪽에 새 자리를 만든다”는 올림의 이유를 발견하게 한다.
- **핵심 화면 텍스트:** `9 + 1 = 10` / `한 자리의 기호가 끝남` / `새 자리`
- **무음 구간:** 미확정 — 새 TTS 승인 후 화면 읽기 시간을 배정한다.

### 장면 2 — 한 자리의 기호를 `0, 1`로 줄이기

- **시간:** 미확정 — 새 TTS 승인 후 결정
- **핵심 시각적 변화:** 한 자리 칸에서 사용할 수 있는 기호 목록 `0~9`가 `0, 1` 두 타일로 줄어든다.
- **필요한 이유:** 올림 규칙은 그대로지만 사용할 기호가 두 개뿐이면 목록의 끝에 더 빨리 도달한다는 사실을 보여 준다.
- **핵심 화면 텍스트:** `0 1 2 … 9` → `0 1` / `한 자리의 기호: 두 개`
- **무음 구간:** 미확정 — 새 TTS 승인 후 화면 읽기 시간을 배정한다.

### 장면 3 — `1 + 1`에서 같은 올림 발생

- **시간:** 미확정 — 새 TTS 승인 후 결정
- **핵심 시각적 변화:** 한 자리의 마지막 기호 `1`에 `1`을 더하면 오른쪽 칸이 `0`으로 돌아가고 왼쪽에 `1`이 올라가 `10₂`가 된다.
- **필요한 이유:** 십진수의 `9 + 1`과 같은 자리 올림이 이진수에서는 `1 + 1`에서 일어난다는 결론을 직접 연결한다.
- **핵심 화면 텍스트:** `1 + 1 = 10₂` / `일 영` / `우리가 평소 세는 2`
- **무음 구간:** 미확정 — 새 TTS 승인 후 `10₂`를 읽을 시간을 배정한다.

### 장면 4 — 다음 질문

- **시간:** 미확정 — 새 TTS 승인 후 결정
- **핵심 시각적 변화:** `1 + 1 = 10₂`의 자리 올림이 남은 뒤 “컴퓨터는 이 올림을 어떻게 만드는가?”라는 질문으로 전환한다.
- **필요한 이유:** 이번 에피소드의 결론을 고정하고 회로 구현은 다음 에피소드로 분리한다.
- **핵심 화면 텍스트:** `컴퓨터는 이 올림을 어떻게 만들까?`
- **무음 구간:** 미확정 — 새 TTS 승인 후 마지막 질문을 읽을 시간을 배정한다.

## 화면 표기와 TTS 발화 규칙

- 화면 표기와 TTS 발화문을 분리한다.
- 십진수의 화면 표기 `10`은 TTS에서 “십”으로 읽는다.
- 이진수의 화면 표기 `10₂`는 TTS에서 “일 영”으로 읽는다.
- TTS 입력 문자열에는 아래첨자 `₂`를 직접 넣지 않는다.
- 화면에서는 `10₂`와 `이진수` 표시를 함께 사용해 수 체계를 구분한다.

## 공통 표시 규칙

- 두 장면에서 같은 자리 칸과 새 자리 생성 동작을 사용해 올림 규칙이 같다는 점을 보여 준다.
- 새 자리는 왼쪽 위치, `새 자리` 문구와 기존 칸과 다른 테두리 모양으로 표시하며 색만으로 구분하지 않는다.
- 사용할 수 있는 기호의 감소는 타일 수, 위치와 숫자 문구를 함께 사용해 전달한다.
- 휴대전화 화면에서 읽을 수 있도록 한 번에 노출하는 보조 문구를 최소화하고 핵심 숫자를 가장 크게 표시한다.
- 전문용어 정의, 반가산기와 논리 게이트는 화면에 넣지 않는다.

## 교육적 정확성 검토

- 십진수에서 한 자리의 마지막 기호 `9`에 `1`을 더하면 오른쪽 자리가 `0`으로 돌아가고 왼쪽에 새 자리 `1`이 생겨 `10`이 된다.
- 이진수에서 한 자리의 기호는 `0`과 `1`뿐이므로 `1` 다음에 같은 올림이 발생한다.
- 이진수의 `10₂`는 십진수 값 `2`이며, 화면 표기와 발음을 구분해 오해를 막는다.
- 회로가 올림을 만드는 구체적인 방법은 이번 에피소드의 범위가 아니며 마지막 질문으로만 예고한다.
