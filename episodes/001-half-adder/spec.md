# 001. 1+1은 왜 10이 될까?—기호가 부족하면 새 자리가 생긴다

## 기본 구성

- 대상: 2진수를 모르는 일반 대중
- 목표 길이: 42초
- 장면 수: 5
- 기본 화면 형식: 9:16 세로형
- 핵심 질문: 한 자리에서 사용할 수 있는 기호를 모두 쓰면 숫자는 어떻게 계속될까?
- 결론: 사용할 수 있는 기호를 모두 쓰면 새 자리를 만들며, `10`은 언제나 십이라는 뜻이 아니라 새 자리가 생겼다는 모양이다.
- 핵심 시각적 변화: 한 자리의 기호 목록이 끝에 도달하면 왼쪽에 새 자리 칸이 열리고, 기존 자리는 `0`으로 돌아간다.
- 설명 순서: 10진수 → 16진수 → 2진수 → 세 경우의 공통 패턴 → 결론과 다음 편 예고
- 범위: 자리 올림의 직관만 설명하고 진법의 정의나 회로 구현은 다루지 않는다.

## 설명 원칙

- `진법(base)`과 `자리값(positional notation)`의 정의는 설명하지 않고 화면의 반복 패턴으로 이해시킨다.
- 10진수, 16진수, 2진수라는 이름은 구분을 위해서만 짧게 사용한다.
- 16진수의 `A~F`는 여섯 개의 추가 기호로만 보여 주고 각각의 값은 설명하지 않는다.
- 세 수 체계에서 같은 애니메이션을 반복해 `기호 소진 → 새 자리 생성 → 현재 자리 0`이라는 공통점을 강조한다.
- 반가산기(Half Adder), XOR(Exclusive OR), AND, NAND는 이번 에피소드에서 언급하거나 설명하지 않는다.
- 다음 편 예고는 마지막 한 문장으로만 제시한다.

## 35~45초 내레이션 초안

### 0:00–0:09

“십진수는 0부터 9까지 열 개의 기호를 씁니다. 9 다음에는 쓸 기호가 없어 새 자리를 만들고 10이 됩니다.”

### 0:09–0:17

“십육진수도 같습니다. 열여섯 기호를 다 써 F에 이르면, 새 자리를 만들어 10₁₆이 됩니다.”

### 0:17–0:26

“이진수의 기호는 0과 1뿐입니다. 1 다음에는 새 자리가 필요하므로, 1 더하기 1은 10₂가 됩니다.”

### 0:26–0:34

“그러니 10이라는 모양이 항상 십을 뜻하지는 않습니다. 기호를 다 써서 새 자리가 생겼다는 뜻입니다.”

### 0:34–0:42

“컴퓨터의 1 더하기 1은 틀린 계산이 아니라 자연스러운 올림입니다. 그런데 컴퓨터는 이 올림을 실제로 어떻게 만들까요?”

## 장면별 스토리보드

### 장면 1 — 열 번째 기호가 필요해진 10진수

- **시간:** 0:00–0:09
- **핵심 시각적 변화:** 한 자리 칸 안에서 `0, 1, 2, …, 9` 타일이 빠르게 지나가고 `9 + 1`에서 다음 기호를 놓을 자리가 비어 있음을 보여 준다. 이어 왼쪽에 새 칸이 열리며 `1`이 들어가고, 기존 칸은 `0`으로 바뀌어 `10`이 된다.
- **필요한 이유:** 시청자가 이미 익숙한 10진수에서 “기호를 다 쓰면 새 자리를 만든다”는 패턴을 먼저 발견하게 한다.
- **핵심 화면 텍스트:** `10진수 (decimal)` / `기호 10개: 0 1 2 … 9` / `9 + 1 → 10` / `새 자리`
- **무음 구간:** 0:08–0:09에 새로 열린 자리와 `10`을 고정한다.

### 장면 2 — 같은 패턴을 반복하는 16진수

- **시간:** 0:09–0:17
- **핵심 시각적 변화:** 장면 1과 같은 한 자리 칸에서 `0, 1, 2, …, 9, A, B, C, D, E, F` 타일이 빠르게 정렬된다. `F + 1`에서 동일한 방식으로 왼쪽 칸이 열리고 `10₁₆`으로 바뀐다.
- **필요한 이유:** `10` 모양이 10진수만의 규칙이 아니라, 사용하는 기호의 개수에 따라 반복되는 패턴임을 보여 준다.
- **핵심 화면 텍스트:** `16진수 (hexadecimal)` / `16개의 기호` / `0 … 9 A B C D E F` / `F + 1 → 10₁₆`
- **무음 구간:** 0:16–0:17에 `10₁₆`과 새 자리 칸을 고정한다.

### 장면 3 — 기호가 두 개뿐인 2진수

- **시간:** 0:17–0:26
- **핵심 시각적 변화:** 긴 기호 목록이 `0`과 `1` 두 타일로 줄어든다. `1 + 1`에서 바로 목록의 끝에 도달하고, 앞선 두 장면과 같은 동작으로 왼쪽 칸이 열리며 `10₂`가 완성된다.
- **필요한 이유:** 2진수에서는 기호가 두 개뿐이므로 1 다음에 곧바로 새 자리가 필요하다는 사실을 직관적으로 연결한다.
- **핵심 화면 텍스트:** `2진수 (binary)` / `기호 2개: 0 1` / `1 + 1 → 10₂` / `새 자리`
- **무음 구간:** 0:25–0:26에 `10₂`와 `2진수` 표시를 함께 고정한다.

### 장면 4 — 세 개의 10에서 공통점 찾기

- **시간:** 0:26–0:34
- **핵심 시각적 변화:** `9 + 1 → 10`, `F + 1 → 10₁₆`, `1 + 1 → 10₂` 세 결과가 세로로 정렬된다. 각 결과에서 새로 생긴 왼쪽 자리의 테두리와 기존 자리의 `0`이 같은 모양으로 맞춰진다.
- **필요한 이유:** `10`의 겉모양보다 “기호를 다 써서 새 자리가 생겼다”는 구조가 핵심임을 한 화면에서 비교하게 한다.
- **핵심 화면 텍스트:** `10은 언제나 십이 아니다` / `공통점: 새 자리 + 현재 자리 0`
- **무음 구간:** 0:33–0:34에 세 결과와 공통점 문구를 고정한다.

### 장면 5 — 1+1=10의 결론

- **시간:** 0:34–0:42
- **핵심 시각적 변화:** 10진수와 16진수 예시는 흐려지고 `1 + 1 = 10₂`만 중앙에 남는다. `틀린 계산` 표시는 지워지고 `자연스러운 올림`이 나타난 뒤, 마지막에 다음 편 질문만 남는다.
- **필요한 이유:** 컴퓨터의 `1 + 1 = 10₂`을 오류가 아니라 같은 자리 올림 규칙의 자연스러운 결과로 이해하게 하고, 회로 설명은 다음 편으로 분리한다.
- **핵심 화면 텍스트:** `컴퓨터에서 1 + 1 = 10₂` / `틀린 계산이 아니다` / `기호가 부족하면 새 자리` / `다음: 올림은 어떻게 만들까?`
- **무음 구간:** 0:41–0:42에 다음 편 질문을 고정한다.

## 공통 표시 규칙

- 세 장면에서 같은 자리 칸, 기호 타일과 새 자리 생성 동작을 재사용해 반복 패턴을 만든다.
- 새 자리는 왼쪽 위치, `새 자리` 문구와 기존 칸과 다른 테두리 모양으로 표시하며 색만으로 구분하지 않는다.
- 각 수 체계의 기호 개수는 타일 수와 숫자 문구를 함께 사용해 전달한다.
- `10₁₆`에는 `16진수`, `10₂`에는 `2진수` 표시를 함께 두어 아래 첨자의 의미를 별도로 설명하지 않아도 구분되게 한다.
- 휴대전화 화면에서 읽을 수 있도록 한 번에 노출하는 보조 문구를 최소화하고 핵심 숫자를 가장 크게 표시한다.
- 전문용어 정의, A~F의 개별 값, 반가산기와 논리 게이트는 화면에 넣지 않는다.

## 교육적 정확성 검토

- 한 자리에서 가장 큰 기호에 1을 더할 때 현재 자리가 `0`으로 돌아가고 왼쪽에 새 자리가 생기는 패턴은 10진수, 16진수와 2진수에 동일하게 적용된다.
- `10`의 값은 사용하는 기호 체계에 따라 달라지므로 `10`이 언제나 십을 뜻한다는 표현을 피한다.
- 이번 설명의 `기호가 부족하다`는 말은 한 자리에서 사용할 수 있는 기호 목록의 끝에 도달했다는 직관적 표현으로 사용한다.
- 회로가 올림을 만드는 구체적인 방법은 이번 에피소드의 범위가 아니며 마지막 질문으로만 예고한다.
